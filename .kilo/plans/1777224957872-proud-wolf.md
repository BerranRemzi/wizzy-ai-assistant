# Project Modularization Plan

## Goal

Split the 1193-line `src/main.cpp` into a maintainable, cohesive module structure that keeps ESP32/PlatformIO conventions, avoids heap bloat, and makes future extension easy.

---

## Proposed Directory Structure

```
src/
├── main.cpp                  # Entry point: setup() + loop() + thin dispatcher
├── config.h                  # Compile-time constants, pins, defaults, test URLs
├── secrets.h.example         # Template for API keys / WiFi (git-safe)
├── core/
│   ├── audio_engine.h        # Audio lifecycle, DMA cleanup, volume control
│   ├── audio_engine.cpp
│   └── callbacks.h           # audio_info, audio_eof_* weak callbacks
│   └── callbacks.cpp
├── network/
│   ├── wifi_manager.h        # WiFi connect, credentials (NVS + secrets)
│   ├── wifi_manager.cpp
│   ├── tts_bridge.h          # ElevenLabs bridge server + task
│   └── tts_bridge.cpp
├── playlist/
│   ├── playlist.h            # Section enums, static arrays, pools
│   ├── playlist.cpp          # Load/parse JSON, random pick, pool logic
│   └── playback.h            # High-level playback requests + sequencing
│   └── playback.cpp
├── storage/
│   ├── sd_manager.h          # SD init, ensure-ready, path helpers
│   └── sd_manager.cpp
├── commands/
│   ├── serial_commands.h     # Serial command dispatcher
│   └── serial_commands.cpp
└── utils/
    └── http_helpers.h        # json_escape, url_encode, read_http_line, read_exact
    └── http_helpers.cpp
```

---

## Module Responsibilities

### `config.h`
- All `#define` constants: pins, volumes, ports, timeouts, playlist paths, test URLs.
- `#include "secrets.h"` fallback with `#if __has_include`.
- Removes magic numbers from all modules.

### `core/audio_engine.*`
- Global `Audio audio(...)` instance.
- `stop_audio_soft()`, `prepare_audio_start()`, `stop_audio_soft_if_active()`.
- `clearDmaBuffer()` wrapper (already in library).
- Volume control helpers.

### `core/callbacks.*`
- `audio_info()`, `audio_showstreamtitle()`.
- `audio_eof_mp3()`, `audio_eof_stream()` → delegate to `playback` module for follow-up logic.

### `network/wifi_manager.*`
- `connect_wifi_from_sources()`: secrets.h → NVS fallback → connect.
- Exposes `wifi_is_connected()` helper.
- Removes WiFi logic from main loop and playback paths.

### `network/tts_bridge.*`
- `tts_bridge_server`, `tts_bridge_task()`, `handle_tts_bridge_client()`.
- `request_elevenlabs_stream_test()`.
- `http_helpers.*` for JSON/URL encoding and HTTP line reading.
- Exposes `tts_stream_active`, `tts_bridge_finished`, `tts_bridge_finished_at_ms`.

### `storage/sd_manager.*`
- `sd_spi`, `sd_ready`, `SD_init()`, `listDir()`, `ensure_sd_ready()`.
- Path building helpers (`build_full_path()`).

### `playlist/playlist.*`
- Static arrays: `g_section_files`, `g_section_count`, enums, pool arrays.
- `load_playlist_from_sd()`, `ensure_playlist_loaded()`, `clear_playlist_data()`.
- `pick_random_file_from_sections()`.
- `unload_playlist_if_loaded()`, `release_playlist_cache_for_playback()`.

### `playlist/playback.*`
- Sequencing state: `category_sequence_active`, `category_waiting_for_followup`, `category_followup_path`.
- `request_sd_file_by_name()`, `request_sd_file_test()`, `play_random_from_pool()`.
- `play_mode_pool()`, `play_random_obrashenija_plus_random_mode()`, `play_startup_system_random()`.
- `request_http_stream_test()`.
- `handle_followup_request()` called from EOF callbacks.

### `commands/serial_commands.*`
- `handle_serial_command()` switch block.
- `run_startup_ramp_test()`.
- Decoupled from `main.cpp` loop.

### `utils/http_helpers.*`
- `json_escape()`, `url_encode()`.
- `read_http_line()`, `read_exact_with_timeout()`.
- Pure utility, no global state.

### `main.cpp` (final)
- Includes + `setup()`: init serial, pins, audio volume, WiFi, SD, TTS bridge, playlist, startup sound.
- `loop()`: serial dispatch, `audio.loop()`, TTS drain check, ramp test check.
- No business logic — pure orchestration.

## Dependencies Flow

```
main.cpp
  ├── core/audio_engine
  ├── core/callbacks → playlist/playback
  ├── network/wifi_manager
  ├── network/tts_bridge → utils/http_helpers
  ├── storage/sd_manager
  ├── playlist/playlist
  ├── playlist/playback → core/audio_engine, storage/sd_manager, playlist/playlist
  └── commands/serial_commands → playlist/playback, network/tts_bridge
```

Circular dependency avoided: `callbacks` calls into `playback` for follow-up, `playback` uses `audio_engine` for start/stop. Forward declarations in headers resolve this.

---

## Key Design Decisions

1. **No heap-heavy refactors**: Playlist stays as static arrays. Only JSON parsing uses temporary heap via ArduinoJson.
2. **`String` minimized**: Only used where already present (follow-up path, TTS URL). All file paths use `char[]` buffers.
3. **Backwards compatible**: Serial commands, EOF behavior, TTS bridge, and startup flow remain identical.
4. **Extensible**: Adding new playback modes, commands, or audio sources only touches the relevant module.
5. **PlatformIO friendly**: All files under `src/`, no extra build flags needed.

## Migration Steps

1. Create `config.h` — extract all constants, `#define`s, and secrets fallback.
2. Create `utils/http_helpers.*` — extract encoding/parsing utilities.
3. Create `storage/sd_manager.*` — extract SD init and path helpers.
4. Create `network/wifi_manager.*` — extract WiFi connect logic.
5. Create `core/audio_engine.*` — extract audio stop/start/volume helpers.
6. Create `playlist/playlist.*` — extract static arrays, JSON load, random pick.
7. Create `playlist/playback.*` — extract playback request functions + sequencing.
8. Create `network/tts_bridge.*` — extract bridge server, task, ElevenLabs request.
9. Create `core/callbacks.*` — extract EOF/info callbacks.
10. Create `commands/serial_commands.*` — extract serial dispatch.
11. Rewrite `main.cpp` — slim entry point importing all modules.
12. Build + verify with `pio run`.
13. Test all serial commands + EOF chaining.

---

## Risk Mitigation

- Each module extracted in its own commit for easy rollback.
- Build after each module extraction to catch include/order issues early.
- All global state stays `static` within its module; cross-module access via explicit getter functions.
